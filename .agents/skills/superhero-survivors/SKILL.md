# Проект Superhero Survivors

Survivors-like (bullet heaven) про супергероев. Godot 4.7.2 .NET, C#, физика Jolt, ассеты KayKit (CC0). **Кодовая база — своя** (решение 09.10): из кита DarkRewar/SurvivorsStarterKit взяты только `addons/` (Jolt), `Objects/` (KayKit), `project.godot`, сцены-каркас. Старые скрипты кита — справка до конца M1, затем удаляются. Не писать новый код по образцу кита.

## Источники правды (читать в этом порядке при старте сессии)

1. `docs/дизайн-документ.md` — концепт, боевка, сложность, экономика, структура забега.
2. `docs/план_первой_недели.md` — неделя 0.5 (чистый фундамент: структура `Scripts/`, задачи, критерии выхода), M1, правила работы.
3. `docs/архитектура-кита.md` — ТЗ для чистой перезаписи: карта того, что должно получиться, и ошибки кита, которые не повторять. Это не образец кода.

Репозиторий: origin = форк AlexVesnov/SurvivorsStarterKit, upstream = DarkRewar/SurvivorsStarterKit. Ветки: `main` (стабильное), `dev` (интеграция), `feature/*` (задачи). Коммиты на русском, кратко.

## Ключевые решения (не переобсуждать без владельца)

- **Одна боевая система.** Авто-оружие (самонаводка, сильно против орд, слабо против элит/боссов) + активные способности (площадь ограничена, сильны против элит/боссов). Никаких фаз и иммунитетов.
- **Комбо через статусы:** способность A вешает статус (Burning/Stunned/Marked), способность B по врагу со статусом даёт усиленный эффект. Комбо-детектор — C# events, конфигурация Resource-файлами.
- **Тайминги только поощряют:** «идеальное нажатие» в широком окне = бонус; промах ничего не срывает. Окна в физических тиках, буферизация ввода 3–5 тиков.
- **Градации врагов:** обычные / элита / мини-босс / босс. Боссы ломаются stagger-баром, не иммунитетом. 5 уровней сложности по образцу Heat (Hades); «обязательность» комбо на топ-уровне выражается через условия (stagger рассеивается, N комбо за фазу), не через обязательные рефлексы.
- **Баланс проверяет решения, не RNG:** на высоких уровнях нужны реролл/продажа апгрейдов.
- **Логика игры — в `_PhysicsProcess`** (тик 60 Гц), не в `_Process`.

## Дорожная карта

- **Структура забега (Brotato-гибрид):** в уровне гемы опыта → левел-ап «1 из 4»; между уровнями магазин за золото (реролл/продажа/комбайн 3→1) — основной двигатель билда; между забегами лёгкая мета-прогрессия. Голосование «мне/врагам» из кита удалено.
- **Неделя 0.5 (чистый фундамент):** паритет с китом на новой архитектуре; структура `Scripts/` — Core (DamageInfo, GameEvents, StatBlock), Player, Combat (AutoWeapon, Ability, статусы, комбо), Enemies, Progression, UI, Levels. Критерий: гемы → левел-ап «1 из 4» → эскалация по таймеру; 200 врагов без просадок; тесты зелёные.
- **M1:** 2 новых авто-оружия (цепная молния, отскок) через базовый AutoWeapon, первый прототип эволюции оружия, юнит-тесты.
- **M2 (go/no-go):** Input Map (Q/E/пробел/ЛКМ/ПКМ), базовый класс Ability, 3 способности, статусы, комбо-детектор. Критерий: 10 минут удовольствия от «поджог → детонация».
- **M3+:** stagger, боссы с фазами, экономика, уровни.

## Конвенции кода

- Структура `Scripts/`: Core / Player / Combat / Enemies / Progression / UI / Levels (схема в плане недели 0.5). Новые системы — в свою папку, не свалку в корень.
- События — централизованная шина `GameEvents` (C# events), не разрозненные подписки.
- Урон всегда через `DamageInfo` (сумма, источник, тип, флаг способности), не голый `uint`.
- Геймплейная логика — только в `_PhysicsProcess` (тик 60 Гц).
- Новое авто-оружие — наследник базового `AutoWeapon`; новая способность — наследник `Ability`. Никаких свитчей на enum по всему проекту.
- Ошибки кита, которые НЕ повторять: сортировка врагов на выстрел, Duplicate() партиклов на хит, аддитивные «+1» вместо StatBlock, логика в `_Process`, хардкод путей к нодам.

## Правила работы с владельцем

1. Сначала обсуждение — потом код. Спорные решения — с аргументами и примерами из игр.
2. Честность важнее угодливости; не хватает данных — сказать, а не выдумать.
3. Движение по этапам, один чат = один этап (спринт). Начало чата: прочитать источники правды выше.
4. ИИ-код — по образцу существующего кода, не с нуля. В конце ИИ-сессии: «объясни, что сделал и почему».

## Тестирование

- Математика урона/статов/комбо — юнит-тесты (xUnit/gdUnit4Net), чистая логика вне Godot.
- Еженедельно: стресс-тест 200 врагов + все спеллы, время кадра в Debugger → Monitors.
- После каждого майлстоуна: полный забег без крашей, счётчики нод не растут.
