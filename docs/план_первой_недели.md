## День 1 — окружение и первый запуск

- [ ] Установить Godot 4.6 .NET, .NET SDK 8, VS Code (C# Dev Kit) или Rider, Git
- [ ] Форкнуть github.com/DarkRewar/SurvivorsStarterKit → клонировать **свой форк**
- [ ] Проверить LICENSE в репозитории (если нет — написать автору; KayKit/Kenney — CC0)
- [ ] Первый запуск (F5). Если краш — реимпорт проекта + перезапуск (особенности Jolt)
- [ ] Проверить Autoload: GameManager (res://Scripts/GameManager.cs) на месте
- [ ] Поиграть 15–20 минут, записать первые впечатления в `заметки/день-1.md`:
  - что уже есть из нашего дизайн-документа «из коробки»
  - что первым бросается в глаза как «хочу переделать»
  - FPS и ощущение плотности врагов

**Результат дня:** проект запускается, играбельная петля работает.

## Неделя 0.5 — чистый фундамент (до M1!)

**Решение (09.10):** код кита не чиним — игровая логика пишется заново. Из кита взяты только `addons/` (Jolt), `Objects/` (KayKit), `project.godot`, сцены-каркас. `docs/архитектура-кита.md` — ТЗ: карта того, что должно получиться, и список ошибок, которые не повторять. Старые скрипты кита лежат рядом как справка до конца M1, затем удаляются.

Новая структура `Scripts/`:
```
Scripts/
├── Core/        # DamageInfo, GameEvents (шина событий), StatBlock (модификаторы)
├── Player/      # Player, движение, статы, радиус подбора
├── Combat/      # AutoWeapon (база авто-оружия), Ability (база способностей), статусы, комбо-детектор
├── Enemies/     # Enemy, EnemyManager (кривая спавна, эскалация по времени, разделение)
├── Progression/ # гемы опыта, левел-ап «1 из 4», золото (магазин — M4)
├── UI/          # HUD, пул цифр урона, экраны
└── Levels/      # таймер уровня, цели, переходы
```

Задачи:
- [ ] **Паритет:** наш код запускает тот же сценарий, что кит сейчас (движение, спавн, 4 оружия, левел-ап) — но на новой архитектуре. Старые скрипты отключены, не удалены
- [ ] **Физический тик 60 Гц:** вся геймплейная логика в `_PhysicsProcess` — фундамент честных таймингов
- [ ] **DamageInfo:** урон всегда через объект (сумма, источник, тип, флаг способности) — база под статусы/комбо
- [ ] **Шина событий (GameEvents):** C# events централизованно; подписчики — UI, комбо-детектор (в M2), аналитика
- [ ] **StatBlock:** базовое значение + аддитивные/мультипликативные модификаторы + пересчёт; реальные статы игрока (HP, броня, скорость, скорость атаки, крит, радиус подбора)
- [ ] **O(n) таргетинг:** ближайший враг — линейный проход с минимумом, пересчёт 2–4 раза/сек, кэш для оружий
- [ ] **Разделение врагов:** push от соседей в радиусе, чтобы орда не слипалась в колонку
- [ ] **Партиклы:** один эмиттер на врага + restart; без Duplicate() на хит
- [ ] **Спавн с эскалацией:** кривая плотности/состава по времени уровня (голосования кита удалены)
- [ ] **Гемы опыта** вместо мгновенного начисления XP + радиус подбора
- [ ] Юнит-тесты (xUnit, чистая логика вне Godot): математика урона/статов, StatBlock

**Критерий выхода:** наш код, наш игровой цикл: гемы → левел-ап «1 из 4» → рост волн по таймеру; 200 врагов без просадок; тесты зелёные. Старые скрипты кита помечены удалением в M2.

## Правила работы (на все спринты)

1. Сначала механики, потом контент, потом красота.
2. ИИ пишет по образцу нашего кода в `Scripts/`, не по коду кита; кит — справка и ТЗ, не образец.
3. Каждую ИИ-сессию заканчивать вопросом «объясни, что ты сделал и почему».
4. Самотест 15 минут вслепую с блокнотом — каждый день, когда менялся геймплей.
5. Прогон полного забега после каждого майлстоуна: без крашей, счётчики нод не растут (утечки).
6. Не более 3 персонажей и 1 уровня до внешних плейтестов.
