# План первой недели: поднять кит и подготовить фундамент

Версия 0.1 — 9 октября 2026
Основа: DarkRewar/SurvivorsStarterKit (Godot 4.6 .NET, C#, Jolt, 3D low-poly вид сверху)

---

## День 1 — окружение и первый запуск

- [ ] Установить Godot 4.6 .NET, .NET SDK 8, VS Code (C# Dev Kit) или Rider, Git
- [ ] Форкнуть github.com/DarkRewar/SurvivorsStarterKit → клонировать **свой форк**
- [ ] Проверить LICENSE в репозитории (если нет — написать автору; KayKit/Kenney — CC0)
- [ ] Первый запуск (F5). Если краш — реимпорт проекта + перезапуск (особенности Jolt)
- [ ] Проверить Autoload: GameManager (res://Scripts/GameManager.cs) на месте
- [ ] Поиграть 15–20 минут, записать первые впечатления в `заметки/день-1.md`:
  - что уже есть из нашего дизайн-документа «из коробки»
  - что первым бросается в глаза как «хочу переделать»
  - FPS и ощущение плотности врагов

**Результат дня:** проект запускается, играбельная петля работает.

## День 2 — чтение кода (с ИИ-ассистентом)

Цель: схема архитектуры на одну страницу в `docs/архитектура-кита.md`.

- [ ] Карта классов: что отвечает за что (спеллы, враги, спавн, UI, прогрессия)
- [ ] Поток урона: TakeDamage, криты, от кого к кому идут события
- [ ] Система спеллов: сцены + скрипты, как ищутся цели, как работают кулдауны
- [ ] Система статов и апгрейдов: где живут числа, как применяются
- [ ] Спавнер и кривая волн: как растёт плотность
- [ ] GameManager (Autoload): что хранит, какие события транслирует
- [ ] HUD: что выводится, где добавлять новые элементы (stagger-бар, шкала героизма)

**Промпт-шаблон для ИИ:** «Объясни, как в этом проекте устроена X. Укажи файлы, классы и поток данных. Затем предложи, куда вписать Y по нашему дизайн-документу.»

**Результат дня:** одностраничная схема, понимание, где делать M1/M2.

## День 3 — процесс и песочница

- [ ] Папка `docs/`, туда — дизайн-документ (уже есть в корне проекта) и схема архитектуры
- [ ] Git-ветки: `main` (стабильное), `dev` (интеграция), `feature/*` (задачи)
- [ ] Тестовая сцена `test_arena.tscn`: плоская арена, кнопка спавна врагов, без волн
- [ ] Репозиторий проекта (не форк кита) завести отдельно: кит — апстрим, наш код — поверх; либо копия кита как стартовый коммит + чистая история
- [ ] Разметить в коде кита TODO-маркеры мест под новые системы (статусы, комбо-детектор, stagger)

**Результат дня:** любой может открыть сцену, нажать кнопку — появятся враги; процесс ветвления понятен.

## Неделя 0.5 — стабилизация фундамента (до M1!)

По итогам разбора кита (см. `SurvivorsStarterKit/docs/архитектура-кита.md`, раздел 8) — без этого M2 строится на шатком.

- [ ] **Реальные статы игрока:** реализовать или удалить `Lifepoints, Strength, Armor, Speed, AttackSpeed` (сейчас есть в enum, не работают)
- [ ] **Физический тик:** перенести геймплейную логику из `_Process` в `_PhysicsProcess` (GameManager — спавн/таймеры, Enemy — атаки/повороты). Тик 60 Гц — фундамент честных таймингов из дизайн-документа
- [ ] **O(n) таргетинг:** заменить `GetNearestEnemy` (сортировка всех врагов на каждый выстрел) на линейный проход с минимумом
- [ ] **Партиклы без дублирования нод:** один эмиттер на врага + restart вместо Duplicate() на каждый хит
- [ ] **Единый канал событий урона:** убрать дубль (Godot-сигнал + C# event), оставить C# event
- [ ] **Разделение врагов:** простой push от соседей, чтобы орда не слипалась в столбик
- [ ] **Проверить глазами** кулдаун Lifesteal (подозрение на баг: удар каждые 0,2 с)
- [ ] **DamageInfo:** заменить `TakeDamages(uint)` на `TakeDamages(DamageInfo)` (сумма, источник, тип, флаг способности) — база под статусы и комбо-детектор
- [ ] Решить судьбу голосований «мне/врагам»: оставить как фичу или заменить временной эскалацией
- [ ] Юнит-тесты на математику урона/статов

**Критерий выхода:** полный забег без просадок на 200 врагах, тесты зелёные, DamageInfo проходит через все 4 оружия.

## Неделя 1–2 — M1 (после стабилизации)

- [ ] 2 новых авто-оружия: цепная молния, отскакивающий снаряд (руками, по образцу кита — изучение системы спеллов)
- [ ] Расширение статов: урон, скорость атаки, криты, радиус подбора, HP, броня
- [ ] Система модификаторов: базовое значение + аддитивные/мультипликативные бонусы + пересчёт
- [ ] Юнит-тесты на математику статов/урона (gdUnit4Net или xUnit, чистая логика вне Godot)
- [ ] Еженедельный стресс-тест: 200 врагов + все спеллы, смотреть время кадра в Debugger → Monitors

**Критерий выхода из M1:** новые оружия работают в полном забеге, тесты зелёные, FPS не просел на целевом железе.

## Правила работы (на все спринты)

1. Сначала механики, потом контент, потом красота.
2. ИИ пишет по образцу существующего кода кита, не с нуля.
3. Каждую ИИ-сессию заканчивать вопросом «объясни, что ты сделал и почему».
4. Самотест 15 минут вслепую с блокнотом — каждый день, когда менялся геймплей.
5. Прогон полного забега после каждого майлстоуна: без крашей, счётчики нод не растут (утечки).
6. Не более 3 персонажей и 1 уровня до внешних плейтестов.
