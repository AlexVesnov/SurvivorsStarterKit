# Промпт для дня 2: чтение кода кита (вставить в ИИ-сессию целиком)

Назначение: один проход по репозиторию DarkRewar/SurvivorsStarterKit с целью получить карту архитектуры и точки встраивания наших систем. Ничего не менять в коде — только читать и объяснять.

---

## Промпт (копировать отсюда)

```
Ты — мой технический ассистент по проекту на Godot 4.6 .NET (C#). Это кит SurvivorsStarterKit (DarkRewar), на его основе мы делаем survivors-like про супергероев. Сейчас фаза изучения кода: ничего не изменяй, только читай и объясняй. В конце каждого пункта указывай файлы и номера строк.

Наш дизайн (для понимания, куда мы идём):
- Единая боевая система: авто-оружие (4–6 слотов) + активные способности на кнопках (Q/E/пробел/ЛКМ/ПКМ) с кулдаунами.
- Система статусов (Burning/Stunned/Marked) и комбо-детектор на событиях: «способность X по врагу со статусом Y → эффект Z», конфигурация данными (Resource-файлы).
- Элиты и боссы с stagger-баром: накопление шкалы → оглушение + окно урона. Боссы 2–3 фазы.
- Расширенные статы: урон, скорость атаки, криты, радиус подбора, HP, броня; система модификаторов (аддитивные + мультипликативные бонусы, пересчёт).
- Мета: опыт (апгрейды в забеге) и золото (магазин между забегами).

Разбор по пунктам:

1. КАРТА КЛАССОВ. Для каждого скрипта в Scripts/ (GameManager, Player, Enemy, EnemyManager, Shooting, FloatingSphereAttack, LifestealAttack, SpiritWater, Powerup, IUpgradable, PowerupPaths, DamageLabelManager, UpgradeView): роль, публичный интерфейс, от каких классов зависит. Итог — таблица.

2. ПОТОК УРОНА. Полная цепочка: от срабатывания атаки игрока до отображения цифры урона. Где вычисляется урон, где применяется к врагу (TakeDamage?), есть ли криты, как работает DamageLabelManager (пулинг?).

3. СИСТЕМА СПЕЛЛОВ/ОРУЖИЯ. Как устроены Shooting, FloatingSphereAttack, LifestealAttack, SpiritWater: общий ли у них базовый класс или интерфейс (IUpgradable?), как ищутся цели, как работают кулдауны и апгрейды. Как добавить НОВОЕ авто-оружие минимальным количеством кода — пошагово, со ссылками на существующий пример.

4. СИСТЕМА СТАТОВ И АПГРЕЙДОВ. Где живут числа (HP, урон, скорость), как Powerup и PowerupPaths связаны с апгрейдами при левел-апе, как устроен экран выбора (UpgradeView). Готов ли код к статам «скорость атаки», «крит», «радиус подбора» или их нужно вводить?

5. СПАВНЕР И ВОЛНЫ. Как EnemyManager спавнит врагов, откуда берётся плотность волн, есть ли кривая эскалации по времени. Где вставить элит-версии врагов и мини-босса?

6. GAMEMANAGER (AUTOLOAD). Что хранит, какие события/сигналы транслирует, кто на него подписан. Подходит ли он за основу для: шкалы героизма, золота, счётчика комбо за забег? Или лучше отдельные Autoload-и?

7. HUD. Что выводит Scenes/HUD.tscn, как добавить новые элементы: stagger-бар босса, шкалу героизма, индикаторы кулдаунов способностей.

8. ТОЧКИ ВСТРАИВАНИЯ. Для каждой нашей системы (статусы, комбо-детектор, активные способности на кнопках, stagger-бар, система модификаторов статов) укажи: к какому существующему классу/событию цепляться, что нужно создать нового, какие риски (сильные связи, которые придётся ломать). Оцени объём работы каждой системы в человеко-днях по шкале S (≤1 день) / M (2–3) / L (4+).

Формат ответа: структурированный markdown, файл+строки в каждом пункте, в конце сводная таблица «система → точка встраивания → объём → риски». Не пиши код реализации — только схемы и ссылки на код.
```

## Как использовать

1. Открой сессию с ИИ (K2.7 Code в Kimi Code или другой ассистент с доступом к папке проекта).
2. Вставь промпт целиком.
3. Результат сохрани как `SurvivorsStarterKit/docs/архитектура-кита.md` (создай папку `docs`).
4. Если ответ обрывается — продолжай фразой «продолжи с пункта N».
5. После получения ответа задай контрольный вопрос: «Теперь кратко: если делать ТОЛЬКО систему статусов + комбо-детектор, в каком порядке трогать файлы?»
