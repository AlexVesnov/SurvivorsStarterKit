## 2. Поток урона

```
Оружие (Shooting.Shoot / Sphere.OnBodyEntered / SpiritWater.OnDamageReady / Lifesteal)
  → Enemy.TakeDamages(uint)                    [Enemy.cs:128]
      → EmitParticles()                        (дублирование GpuParticles3D на каждый хит — риск при орде!)
      → EmitSignal(OnEnemyHit)                 → подключён в EnemyManager.SpawnEnemy:62 → GameManager.EnemyHit
      → Lifepoints -= урон; ≤0 → QueueFree()
  → GameManager.EnemyHit → C# event OnEnemyHit → DamageLabelManager показывает цифру
  → TreeExiting → EnemyManager.KillEnemy → GameManager.EnemyKilled(xp) → XP-бар → левел-ап
```

Проблемы потока:
- Урон — голое `uint`, **без источника, типа, крита**. Для статусов/комбо-детектора сигнатуру придётся расширять (см. раздел 7).
- Двойная подписка на одно событие: и Godot-сигнал, и C# event `OnEnemyHit` — избыточно, легко рассинхронизировать.
- `EmitParticles` дублирует ноду партиклов **на каждый удар** — при плотном огне и 200 врагах это лишние аллокации нод.

## 3. Система спеллов/оружия

- Общий контракт только `IUpgradable.Upgrade(PowerupType)` — **нет базового класса оружия**. Каждое оружие само держит Timer, само ищет цели, само апгрейдится свитчем.
- Поиск цели: `GameManager.GetNearestEnemy()` — **OrderBy по всем врагам на каждый выстрел** (GameManager.cs:181). O(n log n) за выстрел; при 200 врагах + 4 оружия = ~800 сортировок/сек. Первый кандидат на оптимизацию.
- Как добавить оружие (минимальный путь, по образцу Shooting): скрипт `Node3D, IUpgradable` + Timer + префаб в `Prefabs/Powerups/` + запись в `PowerupPaths.PlayerPowerups` + .tres в `Powerups/`.

## 4. Система статов и апгрейдов — ⚠️ не работает

- В enum `PowerupType` заявлены статы игрока: `Lifepoints, Strength, Armor, Speed, AttackSpeed` (Powerup.cs:17–23) — **ни один не обрабатывается нигде**. Никто не реализует `Upgrade` для них: ни Player, ни оружия. Записей .tres для них в PowerupPaths нет. Скорость/HP игрока меняются только дефолтными значениями.
- Апгрейды оружий — аддитивные «+1 к урону» внутри каждого оружия. Общей системы модификаторов (база + аддитивные × мультипликативные) нет.
- Кривая XP: `GetMaxXPPerLevel` = `log10(level^10 × 10) × 5` (GameManager.cs:185).
- Скрин выбора: 3 случайных апгрейда игрока + **3 случайных баффа врагам** — игрок голосует парой «мне / врагам». Это фирменная механика кита (Brotato-подобный трейдофф), в нашем дизайне не запланирована — решить: оставить как опцию или убрать.

## 5. Спавнер и волны

- Спавн: **1 враг/сек фиксированно**, потолок 200, без эскалации по времени (GameManager.cs:76–88). Рост сложности — только через голосования (разблокировка классов Warrior/Archer/Mage, HP/урон/скорость/спавнрейт врагов, спавн босса).
- Босс — просто префаб `enemy_boss.tscn` с флагом класса. Без фаз, без механик, вызывается debug-кнопкой `SpawnBoss` или голосованием.
- Кривая HP врагов: `log10(level × 10)` (GameManager.cs:187) — мягкий рост.
- Место для элит/мини-боссов: `EnemyManager.SpawnEnemy(EnemyClass)` + новые значения в enum + новые префабы.

## 6. GameManager и HUD

- GameManager (Autoload) хранит: Player, XP/уровень, GameTime, списки паверапов, состояние голосования. `ProcessMode = Always` — работает на паузе.
- Транспорт событий: C# events (`OnEnemyHit`, `OnChoose`). Сигналов Godot почти нет. **Для комбо-детектора идеально ложится C# event-центр** (см. раздел 7).
- HUD — простой Control: таймер, XP-бар, HP-бар, контейнер выбора. Новые элементы (stagger-бар, шкала героизма, кулдауны способностей) добавляются в HUD.tscn + доступ из кода по пути `/root/MainScene/HUD/...`.

## 8. ⚠️ Что починить до M1 (неделя 0.5 «стабилизация»)

Дефекты кита, которые дешевле закрыть сейчас, чем строить на них:

1. **Неработающие статы** (`Lifepoints, Strength, Armor, Speed, AttackSpeed`) — либо удалить из enum, либо реализовать. Сейчас это ловушка: «есть в коде, не работает».
2. **`GetNearestEnemy` — сортировка всех врагов на каждый выстрел** → заменить на линейный проход с минимумом (O(n)) или индекс ближайших (периодический пересчёт 2–4 раза/сек).
3. **`EmitParticles` дублирует ноду партиклов на каждый хит** → один общий эмиттер врага + restart, или пул.
4. **Логика на `_Process` вместо `_PhysicsProcess`** в GameManager и Enemy — тайминги зависят от FPS рендера. Перенести геймплейный тик (спавн, атаки, движение) на физический тик 60 Гц — это же фундамент под честные тайминги из дизайн-документа.
5. **Двойное событие урона** (сигнал + C# event) — оставить один канал (C# event, он удобнее для комбо).
6. **Враги двигаются сквозь друг друга** (`GlobalPosition +=` без разделения) — при 200 врагах они слипаются в столбик. Ввести простое разделение (push от соседей в радиусе) или хотя бы ограничение.
7. **Подозрительный кулдаун Lifesteal**: `WaitTime = 1f / TotalCooldown` при Cooldown=5 даёт удар каждые 0,2 с — вероятно баг, проверить глазами в игре.
8. **Решить судьбу голосований «мне/врагам»** — оставить как фичу или заменить временной эскалацией по дизайн-документу.

## 9. Порядок работ (скорректированный)

1. **Неделя 0.5:** пункты 1–8 раздела 8 + DamageInfo (S). Итог: чистый фундамент.
2. **M1 (нед. 1–2):** 2 новых авто-оружия (цепная молния, отскок) по образцу + StatBlock для статов оружия + юнит-тесты математики.
3. **M2 (нед. 3–5):** Input Map + Ability-база + 3 способности + статусы + комбо-детектор. Go/no-go как было.
4. **M3+:** без изменений (stagger, боссы, экономика, уровни).

Красная нить: кит даёт «ноги» (рендер, физика, KayKit, базовая петля), но ядро — DamageInfo → статусы → комбо — строим сами, и строим на починенном фундаменте, а не на сыром прототипе.
